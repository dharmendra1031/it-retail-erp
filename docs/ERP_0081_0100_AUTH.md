# ERP-0081–0100: Authentication, CSRF and session lifecycle

Source: SRS §§6, 7, 57, 59. Owner: WP05. Current API endpoints are `/api/auth/csrf` (GET), `/api/auth/login` (POST), `/api/auth/me` (GET), `/api/auth/logout` (POST).

## Shared policy and implementation

- Both backends use server-side session cookies, authenticated `me`, protected logout and the `X-CSRF-TOKEN` request header for mutations.
- Missing or incorrect login credentials: HTTP 401; invalid login data: HTTP 400. Mutations without a valid CSRF token: HTTP 403 on both backends. An expired/invalid session returns HTTP 401 and React returns to Login.
- 5 incorrect passwords lock an existing account for 15 minutes; success resets the lockout counter. Django stores `failed_login_attempts` and `locked_until` in its User table with a migration and serializes attempts inside a database transaction. ASP.NET Core uses standard Identity lockout.
- Inactive users are denied by authentication. Idle session cookie lifetime: 30 minutes. `rememberMe` preserves the session cookie across browser restarts until expiration; without it, use a session cookie. Django refreshes the cookie lifetime on activity; ASP.NET cookie sliding expiration is enabled.
- ASP.NET Core IdentitySeeder creates/assigns an Admin role when explicit `ERP_ADMIN_EMAIL`/`ERP_ADMIN_PASSWORD` are supplied. Django `python manage.py seed_admin` does the same, idempotently, and does not overwrite an existing password. Neither backend contains a built-in deployment admin password.
- React uses `frontend/src/api/client.ts` and one application-wide session-expiration notification. The Login, Company and Role forms share one keyboard navigation helper; labels/error feedback support English/Arabic through a single dictionary and RTL switch.
- User/company and role operations still require server authorization; hiding React controls is not permission enforcement.

## Negative acceptance and tests

- Invalid passwords, five-failure lockout, expiry, missing CSRF, missing/invalid login details, anonymous Company/Role access and role restrictions.
- Django `accounts.tests` and SQL Server integration tests; ASP.NET API smoke, lockout script and Identity test database; Playwright EN/AR, Enter key navigation, Company/Role and expired cookie.
