## Actual backend implementation

| Area | ASP.NET Core | Django | Verified source observation |
| --- | --- | --- | --- |
| Entity/model | `aspnet-core/src/ITRetailERP.Web/Models/Product.cs` | `django/apps/catalog/models.py` (`Product`) | Single numeric `long`/`BigAutoField` ID; separate English/Arabic names and descriptions; SKU, optional barcode, Category, optional Brand, required Unit, `stock/nonstock/digital`, serial flag, cost/base/min price, reorder and active flag. |
| Request and response | `Contracts/ProductRequest.cs` | `ProductSerializer` in `django/apps/catalog/api.py` | Camel-case Product API contracts. Currency decimals stored to three digits, reorder level to six digits; ASP.NET returns fixed-format strings, DRF `DecimalField` serializes strings under current API defaults. Cross-backend response parity requires dedicated checks in WP16. |
| Routing and CRUD | `Controllers/Api/ProductsApiController.cs` | `ProductViewSet` plus `django/config/api_urls.py` | Both expose GET list/detail, POST, PUT and DELETE under `/api/products`. Django router uses no trailing slash. |
| SKU and barcode | `Valid`, `Barcode`, `Apply` | `validate_sku`, `validate_barcode` | Normalize to trimmed upper-case; accept SKU `[A-Z0-9_-]{1,40}` and optional barcode `[A-Z0-9_-]{3,64}`. Preflight duplicate checks present. Race-path error parity still requires testing. |
| Product relationships | `Valid` checks active Category/Unit/optional Brand | Active queryset in `PrimaryKeyRelatedField` | Category + Unit required, Brand optional; product use prevents parent master deletion through SQL FK/DRF PROTECT (recorded in existing integration/unit tests). |
| Product search | `ProductsApiController.List` | `ProductViewSet.get_queryset` | Current `?search=` queries **SKU only**. English/Arabic product name, item code and barcode search from the SRS is not implemented. |
| Permissions | `[Authorize(Policy="products.*")]` and CSRF on mutating actions | `CatalogViewSet` / `CatalogPermission` | View/add/edit/delete policies declared. Non-admin permission and product mutation denial should be tested specifically in WP16. |
| Data-safety edge cases | `SaveChangesAsync`, hard delete | `CatalogViewSet` wraps create/update in `transaction.atomic`; `destroy` catches `ProtectedError` | The ASP.NET Product create/update/delete methods do not translate concurrent database unique/FK exceptions to clean API error responses. Django's general `IntegrityError` fallback returns 400; `ProtectedError` returns 409. Record parity gap for ERP-0303/0312/0313. |

## Database and indexes

- ASP.NET Core: `Data/ApplicationDbContext.cs` and `Migrations/20261023140000_Products.cs` declare `BIGINT IDENTITY(1,1)`, NVARCHAR text, unique `Sku`, filtered unique `Barcode` when non-null, Category/Brand/Unit foreign-key indexes and restrict-on-delete, `decimal(18,3)` for price and `decimal(18,6)` for reorder.
- Django: `apps/catalog/models.py` and `migrations/0002_product.py` declare `BigAutoField`, unique `sku`/`barcode`, `DecimalField(18,3)`/ `(18,6)` and PROTECT foreign keys. SQL Server indexes for Django uniqueness are generated by model migrations; inspect actual schema in disposable SQL tests before asserting identical physical index names/filters.
- Existing schema contains no separate `ItemCode`, `Model`, `WholesalePrice` or `TaxCategory` columns. Tax engine, initial/current stock and warranty linkage are owned by later packages per `ERP_0301_PRODUCT_SCOPE.md`.
- No new migration is needed for this inventory step. Existing migrations are **not** a substitute for tested future schema changes, rollback or Product-specific concurrency checks. No production DB accessed.

## React inventory and actual UI gaps

Inspected `frontend/src/App.tsx`, `components/AppShell.tsx`, `components/Catalog.tsx` and `api/catalog.ts`:

- `App.Page` has Company, Role, User, Organization, Customer, Supplier, Category, Brand and Unit screens but **no Product page** or Product menu.
- `CatalogKind` permits only `categories | brands | units`; there is **no Product API client**, Product interface, Product form/list or Product create/edit/delete feedback UI.
- Existing shared Catalog offers Category/Brand/Unit lists and selectors for Category hierarchy, but **no Product Category/Brand/Unit selectors**.
- Catalog search filters its downloaded rows client-side; neither Product-specific filtering nor pagination exists.
- Product keyboard-only navigation, English/Arabic forms, responsive layout and Playwright browser coverage have not been implemented; follow project conventions instead of duplicating generic React scaffolding.

## Test inventory and gaps

- `django/apps/catalog/tests.py` `ProductApiTests` checks bilingual Product creation, unique SKU/barcode, required relationships, invalid prices, nonstock settings and referenced-master delete conflicts.
- `aspnet-core/tests/smoke_sqlserver.py` creates a Product against disposable SQL Server, checks duplicate SKU/non-stock rules and protects referenced master records.
- `aspnet-core/tests/ITRetailERP.Tests/CatalogValidationTests.cs` tests Category/Brand/Unit validation; it does not provide a dedicated Product validation unit suite.
- `frontend/e2e/erp.spec.ts` has no Product-specific browser flow in current source.
- Existing baseline CI [40442028840](https://github.com/dharmendra1031/it-retail-erp/actions/runs/40442028840) completed 5/5 successfully on the reviewed commit. It does **not** establish full Product Master E2E, search, pagination or concurrent duplicate safety.
